# تحویل انتشار استاتیک — رهاورد تکلان

Task 09-C · تاریخ تهیه: ۲۰۲۶-۱۰-۲۲ · وضعیت: بسته محلی آماده؛ روی سرور واقعی منتشر نشده است.

## ۱. تصمیم انتشار و نسخه ابزارها

با تصمیم صریح مالک، انتشار فعلی کاملاً استاتیک است. Backend و Database در مرحله آینده و فقط با درخواست جداگانه اجرا می‌شوند. این تصمیم ترتیب زیرساختی PDF را فقط برای این انتشار جایگزین می‌کند؛ سایر الزامات معتبرند. طراحی و داده‌های تثبیت‌شده در 09-B حفظ شده‌اند.

نسخه‌های بررسی‌شده: Node.js `24.19.0`، npm `11.17.0`، Astro `7.4.0`، Tailwind CSS و افزونه Vite آن `4.3.3`، TypeScript `6.0.3`، Astro Check `0.9.12`، Vazirmatn `5.3.0`. حداقل Node تعریف‌شده پروژه `22.22.0` است. نصب وابستگی‌ها با lockfile انجام شود؛ تغییر نسخه مستقل انجام نشود.

در ریشه پروژه، روی دستگاه ساخت:

```powershell
npm ci
npm run astro -- check
npm run build
```

`npm ci` راهنمای ساخت مجدد است؛ در این تسک وابستگی جدیدی نصب نشده است. نتیجه واقعی Check: ۴۱ فایل، صفر خطا، صفر هشدار، صفر Hint. Build موفق بود.

## ۲. خروجی و بسته قابل تحویل

خروجی `dist/` است. بسته `output/static/rahvard-taklan-static-2026-10-22.zip` فقط **محتویات** این پوشه را دارد؛ `index.html` در ریشه ZIP قرار دارد. فایل SHA256 کنار ZIP برای کنترل سلامت انتقال است.

خروجی شامل ۵۳ فایل با حجم بازشده ۱۰٬۰۱۷٬۵۸۳ بایت است: ۱۹ HTML، دو CSS، سه JavaScript، سه WOFF2 و سایر تصاویر/مجوزها/آیکون‌ها. HTMLها: خانه، دو صفحه کاتالوگ، ۱۱ جزئیات محصول، سه صفحه تماس/درباره/حریم خصوصی، یک مسیر انتقال قدیمی و 404.

## ۳. روش آپلود

محتویات ZIP را در DocumentRoot واقعی دامنه استخراج کنید؛ نام این پوشه به هاست وابسته است. پوشه `dist` را به‌عنوان یک لایه اضافی آپلود نکنید. ساختار `_astro/`، `images/`، `fonts/` و پوشه‌های صفحات حفظ شود. میزبانی نباید فایل‌های `_astro` را مسدود کند.

سورس، `node_modules`، `.git`، فایل‌های محیطی، ابزارهای QA و مستندات پروژه جزو بسته وب نیستند. هنگام جایگزینی انتشار، از فایل‌های اختصاصی میزبان نسخه پشتیبان بگیرید و انتشار را به‌صورت هماهنگ جایگزین کنید تا HTML جدید با asset قدیمی مخلوط نشود.

## ۴. نیاز زمان اجرا

برای نمایش و کارکرد امکانات فعلی، **Node.js، Astro runtime، Python، Database یا API روی سرور لازم نیست**. وب‌سرور معمولی فایل‌های HTML/CSS/JS و تصاویر را سرو می‌کند؛ جست‌وجو و گالری در مرورگر اجرا می‌شوند. Node فقط روی دستگاه Build لازم است. فایل‌سرور Python استفاده‌شده در QA صرفاً ابزار محلی آزمون است و بخشی از سایت نیست. مطابق [راهنمای انتشار Astro](https://docs.astro.build/en/guides/deploy/)، خروجی استاتیک از پوشه build قابل تحویل به میزبان است.

## ۵. URL و اسلش پایانی

تنظیمات صریح فعلی: `output: 'static'`، `build.format: 'directory'`، `trailingSlash: 'ignore'`. این‌ها رفتار پیش‌فرض قبلی را تثبیت کرده‌اند؛ URL تأییدشده‌ای تغییر نکرده است. لینک‌های اصلی سایت عموماً اسلش پایانی دارند.

رفتار واقعی URLهای فایل استاتیک را وب‌سرور تعیین می‌کند؛ `trailingSlash` به‌تنهایی قانون redirect میزبان نیست. مسیر پوشه بدون اسلش ترجیحاً با redirect به همان مسیر دارای اسلش برود و query string حفظ شود. [مرجع تنظیمات Astro](https://docs.astro.build/en/reference/configuration-reference/#trailingslash).

## ۶. index.html و مسیرهای داخلی

برای نمونه `/products/product-1/` باید `products/product-1/index.html` را نمایش دهد. `/products/page/2/` نیز فایل index مستقل دارد. Directory index باید فعال باشد؛ directory listing عمومی لازم نیست. همه مسیرهای داخلی باید با ورود مستقیم و Refresh کار کنند. سایت SPA نیست؛ تمام مسیرها را به index صفحه اصلی با وضعیت 200 بازنویسی نکنید.

## ۷. صفحه ناموجود

میزبان باید `404.html` را برای مسیر ناموجود با **HTTP 404** نمایش دهد. وجود فایل به‌تنهایی تنظیم میزبان را تضمین نمی‌کند. پیکربندی مربوط به نوع واقعی وب‌سرور است. فایل‌سرور محلی QA این رفتار را صریح تنظیم و تأیید کرده است؛ روی میزبان نهایی دوباره آزموده شود.

## ۸. انتقال‌های موجود

`/products/demo-1hm919051m/` به `/products/product-1/` می‌رود. در خروجی استاتیک فعلی، HTML انتقال با meta refresh ساخته شده و خود فایل وضعیت 200 دارد؛ این به معنی HTTP 301 نیست. مقصد در مرورگر بررسی شد. اگر انتقال دائمی HTTP لازم است، مسئول سرور باید پس از تعیین نوع میزبان قانون 301 همین مسیر را تنظیم کند. فایل تنظیم قطعی Apache/Nginx برای هاست نامشخص ساخته نشده است.

## ۹. تصمیم‌های وابسته به میزبان و دامنه

بسته فعلی برای **ریشه دامنه** است. دامنه، DNS، TLS/HTTPS، دامنه اصلی www یا بدون www، redirectها، MIME درست CSS/JS/WOFF2 و سیاست cache/فشرده‌سازی باید با مسئول میزبان مشخص شوند. HTML نباید در cache طولانی ناسازگار با انتشار جدید باقی بماند؛ assetهای hashدار را می‌توان مطابق قابلیت میزبان cache کرد.

اگر نصب در زیرپوشه درخواست شود، ابتدا نام واقعی مسیر تأیید شود. تنظیم `base` به‌تنهایی برای پروژه فعلی کافی نیست: تعدادی لینک و مسیر تصویر/CSS از `/` آغاز می‌شوند و باید متناسب با زیرپوشه اصلاح، Build و آزمون مجدد شوند. ZIP فعلی را بدون این کار برای subpath آماده فرض نکنید. هیچ دامنه یا مسیر میزبانی حدس زده نشده است.

## ۱۰. تغییر محتوا و ساخت مجدد

محصولات از `src/data/products.ts` و fixture اول از `src/data/product-detail-demo.ts` تأمین می‌شوند؛ اطلاعات عمومی تماس در `src/data/company.ts` است. متن‌های صفحات در فایل‌های مربوط به همان صفحات/کامپوننت‌ها قرار دارند. فقط اطلاعات تأییدشده را ویرایش کنید، id/slug و صفرهای ابتدای کد را حفظ کنید، سپس Check، Build و آزمون روی خروجی جدید انجام دهید. تغییر فایل TypeScript روی هاست استاتیک اثری ندارد؛ باید خروجی جدید آپلود شود. انتخاب فناوری ذخیره‌سازی آینده جزو این تحویل نیست.

## ۱۱. امکانات فعال و غیرفعال

فعال: صفحات ثابت، گالری، جست‌وجوی نام/کد، مرتب‌سازی، صفحه‌بندی، انتقال انتخاب محصول به Contact، لینک تلفن و مسیریاب. تعاملات کاتالوگ/گالری نیازمند JavaScript مرورگرند؛ ساختار HTML و صفحات کاتالوگ مستقل ساخته شده‌اند.

عمداً غیرفعال: ثبت/ارسال آنلاین درخواست، ذخیره اطلاعات، پیام موفقیت ثبت، Backend/API، Database، احراز هویت و مدیریت فروش. دکمه ارسال فرم غیرفعال باقی مانده است. فیلترهای دسته‌بندی/برند/مدل به علت نبود داده approved غیرفعال‌اند؛ جست‌وجو و مرتب‌سازی فعال‌اند. شماره فروش از `company.ts` خوانده می‌شود.

فونت و تصاویر سایت محلی‌اند. نقشه تعبیه‌شده Google و لینک‌های Google Maps/نشان/بلد خدمات بیرونی‌اند؛ دسترسی آن‌ها به اینترنت و وضعیت ارائه‌دهنده وابسته است و با Build موفق تضمین نمی‌شود.

## ۱۲. آزمون پذیرش پس از آپلود

روی دامنه واقعی این مسیرها را مستقیم باز و Refresh کنید:

- `/`، `/products/`، `/products/page/2/`
- هر ۱۱ مسیر `/products/product-1/` تا `/products/product-11/`
- `/contact/`، `/about/`، `/privacy/`
- `/products/demo-1hm919051m/` برای انتقال
- یک مسیر ناموجود برای بررسی ظاهر و HTTP 404
- `/products?q=test` برای حفظ query هنگام افزودن اسلش

جست‌وجوی «محصول شماره ۱۱» و کد `1HM919051M` با حروف کوچک و ارقام فارسی، مرتب‌سازی نزولی، صفحه دوم، حالت بدون نتیجه، گالری چهارعکسی محصول اول، `/contact/?product=product-1` پس از Refresh و حذف انتخاب را کنترل کنید. ارسال باید غیرفعال بماند. Console/Network، بارگذاری فونت، تصاویر، ده لینک فهرست حریم خصوصی، تماس، RTL و عرض‌های 1440/768/390/360 را بررسی کنید.

### نتیجه واقعی آزمون محلی این تحویل

خروجی `dist` با فایل‌سرور مستقل روی loopback سرو شد؛ Astro dev/preview در سرو این خروجی دخالت نداشت. ورود مستقیم و Refresh تمام ۱۸ صفحه غیرانتقالی، انتقال قدیمی، جست‌وجو، مرتب‌سازی، صفحه‌بندی و گالری/Contact موفق بودند. صفحه دوم با JavaScript آدرس را به `/products/?page=2` نرمال می‌کند و محصولات ۱۰/۱۱ را نشان می‌دهد؛ فایل مستقل صفحه دوم نیز موجود است. تمام ده مقصد فهرست Privacy موجود بودند.

هر ۵۳ فایل خروجی با HTTP 200 دریافت و بایت‌به‌بایت با dist مقایسه شد؛ ۳۶ مسیر محلی موجود در HTML به فایل واقعی می‌رسند. 404 سفارشی با وضعیت 404 و redirect پوشه با حفظ query تأیید شد. اسکن HTML/CSS/JS مسیر localhost، IP توسعه، Windows، file URL یا ابزار dev پیدا نکرد. در بررسی Console خطای برنامه مشاهده نشد. فونت `Vazirmatn` loaded و زبان/جهت `fa/rtl` بود؛ تصویر شکسته قابل مشاهده یافت نشد. عنصر تصویر بدون src در Contact فقط جای‌نگهدار مخفی انتخاب محصول است.

عرض واقعی مرورگر این آزمون **1280px** بود؛ کنترل تغییر viewport ابزار اعمال نشد. تکرار بررسی شش صفحه در اندازه‌های درخواستی نیز عملاً در همان 1280 اجرا شد، بنابراین آن را آزمون مستقل موبایل/1440 محسوب نمی‌کنیم. در عرض واقعی 1280 اسکرول افقی نبود. بررسی واقعی عرض‌های هدف روی میزبان یا مرورگر دارای کنترل اندازه هنوز لازم است. آزمون‌های Responsive گزارش‌شده در 09-B متعلق به مرحله قبلی‌اند و جای آزمون این بسته را نمی‌گیرند.

مدارک محلی: `tmp/09c-qa/output-check.json` و `tmp/09c-qa/production-desktop.png`؛ این‌ها داخل ZIP انتشار قرار ندارند.

## ۱۳. وضعیت انتشار محتوا و SEO

هر ۱۱ محصول همچنان `ui-demo` و صفر محصول approved است. هشدارهای نمایشی بودن داده‌ها حفظ شده‌اند. محصولات، کاتالوگ و 404 دارای noindex هستند؛ مسیر انتقال نیز noindex/canonical مقصد دارد. صفحات خانه/درباره/تماس/حریم خصوصی بی‌دلیل noindex نشده‌اند. noindex کنترل دسترسی یا تضمین عدم دیده‌شدن نیست.

فعلاً `robots.txt`، `sitemap.xml` و canonical سراسری صفحات عادی ساخته نشده‌اند؛ دامنه قطعی در اختیار نیست. پس از تأیید دامنه و محتوای واقعی، canonical و sitemap و robots متناسب با تصمیم انتشار بررسی شوند. noindex داده آزمایشی خودکار حذف نشود. ثبت وضعیت approved صرفاً بر مبنای بازبینی واقعی شرکت انجام شود.

انتشار عمومی همین محتوای آزمایشی، ادعاهای موجود شرکت، اطلاعات تماس و متن پیش‌نویس حریم خصوصی نیازمند تأیید محتوایی مالک است؛ آماده بودن فنی بسته این تأیید را ایجاد نمی‌کند. لوگوی PNG فعلی حدود ۱٫۱۲MB است؛ اصل تصاویر بزرگ بنر نیز در public حفظ و به خروجی کپی شده‌اند، هرچند صفحه از نسخه‌های WebP موجود استفاده می‌کند. این فایل‌های اضافی حجم ZIP را بالا می‌برند؛ برای حفظ دارایی‌ها حذف یا بازتولید نشدند.

**جمع‌بندی:** بسته از نظر معماری، بدون Backend و بدون Node در زمان بازدید قابل انتشار استاتیک روی ریشه دامنه است؛ تنظیم میزبان، بازبینی اندازه‌های هدف و تأیید محتوای عمومی هنوز باید انجام شود. اتصال به سرور واقعی یا Deployment در این تسک انجام نشده است.
